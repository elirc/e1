# Test the booking contract through actual consumers

The suite is one file, `src/tests/booking-flow.test.ts`, with 18 tests (nine of them generated by the loop at lines 49-55). It uses Node's built-in test runner and `scripts/alias-loader.mjs`, which resolves `@/` imports to `src/` and redirects `next/server` to `next/server.js`. It invokes real service functions and actual route handlers; no database container is involved because this application's storage boundary is deliberately in memory. Type checking remains a separate command (`npm run typecheck`) because runtime type stripping does not verify types.

## Running it

```
npm test
```

On a clone without `node_modules`, the same command reports `# pass 17 / # fail 1`: only the HTTP test fails, with `Cannot find package 'next'`. That is a quick way to confirm your environment before installing anything. To run a single test while debugging, add `--test-name-pattern`:

```
node --loader ./scripts/alias-loader.mjs --experimental-strip-types --test --test-name-pattern "reschedule" src/tests/booking-flow.test.ts
```

## The fixture

`fixture()` (`:12-23`) uses a fixed Monday 08:00 UTC clock and creates two published event types (`event` and `other`) for one organizer, with identical 09:00-18:00 hours every day and all buffers and notice set to zero. That removes unrelated seed calendar data from conflict tests. Each call constructs its own repository and service, so buffers, guest flags and clocks can be varied per test. When a test needs a different clock it mutates `f.options.clock` and builds a *new* service (`:73`), because `createBookingService` captures `options.clock` once at line 24.

The fixture copies the seed's first event type and template with `structuredClone` and then overrides fields. If a future seed change adds a field that `generateSlots` reads, the fixture inherits it silently; check the seed first when a fixture test fails for no obvious reason.

## Why the shared-repository test matters

Isolated service tests cannot discover a forgotten seed-array read in a page data helper. Lines 26-41 exercise the default demo graph and reset the shared repository in `finally`, so a failing assertion does not leak a booking into the next test. Note that `getPublicBookingPage` and `getDashboardSnapshot` call `new Date()` themselves, so this test depends on the seed's relative times (`isoFromNow`, `src/lib/demo-data.ts:25`) rather than the fixed fixture clock.

## Debugging recipe

1. Reproduce the smallest failing assertion with `--test-name-pattern`.
2. Classify the failure. A type error belongs to `npm run typecheck`. An `ERR_MODULE_NOT_FOUND` is a loader or install problem and happens before any assertion. A `RangeError` comes from the `generateSlots` guard (`availability.ts:86-95`), meaning the event configuration is invalid, not that the slot is taken.
3. For an unexpected 409 from `offered`, call `generateSlots` directly with the same clock, event, template and bookings and print the first few `startTime`s. Most surprises are a non-UTC template timezone, `minNoticeMinutes`, or a blocker from the *other* event type's buffer.
4. For an unexpected 500 from a route, remember `bookingFailure` hides the message. Call the service function directly in a test to see the real error.

Keep the recorded unsuccessful command logs as history, and use only terminal passing runs as delivery evidence.

## Source excerpt

From [src/tests/booking-flow.test.ts](../src/tests/booking-flow.test.ts) (lines 26-41).

```ts
test("create, detail, token, dashboard and preview share the actual demo repository", () => {
  bookingRepository.reset();
  try {
    const event = getEventTypes().find(event => event.published)!;
    const slot = getPublicBookingPage(event.profileSlug,event.slug)!.slots[0]; assert.ok(slot);
    const result = createBooking({ eventTypeId:event.id,startTime:slot.startTime,attendeeName:"Integration Guest",attendeeEmail:"flow@example.com" });
    assert.equal(getBookingById(result.booking.id)?.status,"confirmed");
    assert.equal(getBookingByToken(result.booking.confirmationToken)?.id,result.booking.id);
    assert.equal(getBookingDetail(result.booking.id)?.attendees[0].email,"flow@example.com");
    assert.ok(getDashboardSnapshot().upcomingBookings.some(item=>item.id===result.booking.id));
    assert.ok(!getPublicBookingPage(event.profileSlug,event.slug)!.slots.some(item=>item.startTime===slot.startTime));
    cancelBooking(result.booking.id,"Changed plans",result.booking.confirmationToken);
    assert.equal(getBookingById(result.booking.id)?.status,"canceled");
    assert.ok(getPublicBookingPage(event.profileSlug,event.slug)!.slots.some(item=>item.startTime===slot.startTime));
  } finally { bookingRepository.reset(); }
});
```
